# Bot 回复上下文

[文档索引](../README.md) · [ADR-0008](../adr/0008-grounded-bot-context.md) · [领域术语](../../CONTEXT.md)

## 当前链路

2026-10-10：用户确认并要求实现“回复对象的稳定人物总结＋当前话题相关记忆＋近期对话”。

`窗口的 anchor + 消息上界 → SQLite 读事务获取回复快照 → Decision → 相同快照 + 新 mood → bot_chat → 原发送队列`。

关键入口：[context_builder.rs](../../crates/core/src/context_builder.rs)、[memory.rs](../../crates/core/src/memory.rs)、[bot.rs](../../crates/core/src/bot.rs)、[decision.rs](../../crates/core/src/decision.rs)、[reply_engine.rs](../../crates/core/src/reply_engine.rs)。

- 同窗口最后一条消息的本地 ID 随 anchor 入队；排队期间到来的下一窗口消息不会混入。重启回放单条消息时以上界等于该消息 ID 恢复，不假装恢复完整旧窗口。
- worker 开始处理时通过 SQLx 异步读取一次快照；人格、关系、人物简档、话题记忆、消息和场景统计在同一个读事务中读取。之后数据库发生变化不会改动这份快照；驱动迁移见[异步访问参考](sqlite-access.md)。
- 消息上界约束近期对话和已知来源；这是开始处理时的资料快照，不是全库历史版本查询。人物简档只保存当前字段值；若其来源晚于旧窗口上界，该字段暂时缺失，不能恢复被覆盖的旧版本。旧无出处记忆也无法精确重建窗口当时的状态。
- Decision 可写入新资料供后续轮次使用，本轮 bot_chat 保留原快照；当前明确陈述仍在 anchor 中。人格不由聊天或归纳改写，mood 仍是现有瞬态值。

## 输入组成与预算

Bot 的 user 输入是结构化 JSON，消息正文中的换行/引号会被转义，不能伪装成另一个发送者字段；这不能代替模型对指令与资料的区分。

| 字段 | 内容与边界 |
| --- | --- |
| `reply_target`、`anchor` | 原始目标 person_id/msg_id；锚点正文最多 4,000 字，超长 `text_truncated=true` |
| `quoted_messages` | 同 chat/type 中解析的引用链，最多三层；每条正文最多 2,000 字 |
| `person_profile.facts` | 只取回复对象的简档，四类字段，每字段最多 200 字、引文 4–240 字 |
| `topic_memories` | 当前对象/当前会话的相关记忆，默认最多 3 条，上限 10；正文最多 800 字，明确标记截断 |
| `recent_messages` | 当前 chat/type、消息上界以内的最近 K 条，默认 20，上限 100；每条最多 2,000 字 |
| `participants` | 锚点/引用/近期对话涉及的人，按 person_id 区分，附当时名片和关系分 |
| `dialogue` | 同 chat/type 近 5 分钟内，确实回复过当前人的最后一条 Bot 消息；正文最多 300 字，旧消息不猜归属 |
| `active_tasks` | 当前 chat_id、当前创建者的最多 3 个 running 任务状态，目标最多 160 字；不是已执行结果 |
| `limitations` | 无人物简档、无相关记忆、引用缺失/有歧义、引用链未完整展开等提示 |

每条消息携带本地 ID、person_id、昵称、时间、外部引用编号、`reply_anchor_id` 和 `speaker_kind`；Bot 旧回答只作衔接，不当作独立事实依据。对话承接与任务状态的具体使用见[语义参与框架](decision-framework.md)。

Bot 的 system + user 默认最多 40,000 **字符**。超出时先将近期对话减少到 5 条，再删减相关记忆和人物简档，必要时继续移除近期对话/名册/任务状态；`optional_context_pruned=true` 表示可选资料被删减。锚点、引用、承接证据和缺失提示仍在，放不下就返回错误，发送路径不调用 bot_chat。reply_len 和 reply_mode 的 system 提示也预留在该预算中。这个限制不是 tokenizer 的 token 预算。

Decision 使用同一快照的精简投影：anchor 500 字、每条窗口消息 160 字、每条引用 300 字；额外带窗口前最多 6 条近期消息、每条约 160 字，按需减少近期消息/窗口消息/记忆/简档/任务状态，将结构化 state 限制在 8,000 字符内。系统 prompt 和模型 tokenizer 的完整 8,192-token 校验仍未实现；窗口内全部高优先级消息＋最后 30 条普通消息的完整筛选也未在本轮补齐。

## 人物简档如何产生

使用独立的 `person_profile_facts` 表，主键为 `(person_id, field)`。它是一份由短字段组成的稳定人物总结，没有每轮生成长篇人物画像，也不递归总结已有摘要。

允许字段：`preferred_name`、`technical_preferences`、`ongoing_projects`、`communication_style`。已有 Decision 和夜间归纳请求可以额外输出 `profile_updates`；旧响应不提供此字段时仍兼容，原 `memory_write` 字符串保留。

```json
{"field":"technical_preferences","value":"长期使用 Rust","evidence_msg_id":123,"evidence_quote":"我长期使用 Rust"}
```

Decision 的更新只能引用当前 anchor 本人的原话；归纳更新另带 `person_id`，只能引用本轮归纳窗口内该人的原话。运行时检查来源范围、会话、作者、逐字引文、长度和敏感内容，拒绝从 `self` 消息生成简档。无依据则保持空缺，不把每日摘要或旧无出处记忆迁移成可信简档。

更大的源消息 ID 才能覆盖同一字段；即使内容不变，也推进更新确认的出处，防止迟到的旧归纳覆盖新确认。同一字段可概括多项偏好，提示要求保留仍适用的已有信息；该概括仍依赖模型判断。来源校验只能证明“引文确实来自本人”，不能证明提炼出的 value 在语义上一定正确。玩笑识别、复杂矛盾判断仍有模型误判风险。

简档随本人明确表达/归纳有效资料逐步建立。首轮升级后空简档属于正常状态，既有每日摘要仍保留为历史索引，没有自动重新提炼所有历史消息。

## 话题记忆如何检索

- 查询取当前问题和已解析引用的内容，不使用其他成员的大量插话确定主题。
- 英文按词、中文按相邻双字生成关键词，过滤部分常见虚词，最多 16 个词。查询用绑定参数，限定 `owner=当前 person` 或 `owner=当前 chat`。个人资料仍遵循既有跨群归并规则；不能拿同名的另一个人的资料。
- SQL 在所属人/群范围内匹配，最多返回最近 128 个命中候选；再按匹配词长度之和排序，时间与 ID 作为同分排序，去掉相同主体的重复内容。不是简单取最新 3 条，也不是语义向量检索。
- 相关性匹配之前不截断成“最新 N 条”，因此旧的匹配记忆不会仅因有大量较新但不相关记忆而消失。候选上限仍可能漏掉较早的命中，SQL 匹配可能扫描该主体的历史记录；没有声称常数时间或全库基准性能。
- 旧数据标记 `legacy_unverified`；显式记忆带原消息 ID及可读引文；夜间归纳带 chat/消息范围并标记“窗口不是逐条证据”。资料缺失/作者不匹配会明确标记。所有记忆都保留原始 source 和更新时间。
- 没有匹配时返回空集，不塞不相关记忆凑数。数字、时间和执行结果不足时要求自然追问或说明不确定；新旧资料冲突时优先理解当前明确陈述并核对。

当前未做语义同义词召回、自动过期删除、跨条记忆的语义冲突合并或置信度评分；这些是后续增强，不以关键词命中宣称解决全部幻觉。

## 引用、迁移与兼容

V6 为消息增加 `external_msg_id`；接收消息和发送成功回执都保存协议编号，原 `reply_to` 保持外部编号含义。引用只在同一 chat/type 内按外部编号查找，且被引消息必须早于引用者；不允许退回本地 msg_id 猜测。相同作者/全文/引用的重复回报可以折叠，编号对应不同内容则标记歧义。旧未保存外部编号的消息无法可靠回填，引用缺失时明确提示。

V6 同时增加长期记忆的 `source_chat_id`、`source_msg_id`、`source_end_msg_id` 和人物简档表。旧消息、记忆、每日摘要均保留；不编造旧来源。显式写入补源消息，归纳写入补源窗口。迁移在原有 IMMEDIATE 事务中完成并支持失败回滚，详见[数据模型](data-model.md)。新表包含在现有数据库备份里。

V7 增加成功发送气泡的本地 `reply_anchor_id`，用来定位当时的回复对象。旧 NULL 保留，不利用邻近时间或昵称回填。人物身份继续按 `p_<QQ>` 归并，改名不产生新身份。

配置仍使用 `[context] budget_chars / k / roster_mem_per`。`roster_mem_per` 是兼容保留的旧键名，含义现在是当前对象/会话的话题记忆总条数；面板标签已改为“话题记忆条数”。这些配置按本轮开始时取值；不需要新模型、API key 或外部检索服务。

## 验证

2026-10-10 本地：`cargo test --workspace` 113 个测试通过；随后补充“Decision 必要信息超预算时不访问 provider”用例，上下文专项 9 个测试全部通过。新增用例覆盖同名成员隔离、旧相关记忆召回、资料更新/伪造出处拒收、快照不混入未来消息、引用编号碰撞/跨群/歧义、预算与空简档；V6 增加失败回滚及旧数据保留测试。已有 QQ/NapCat mock 回复闭环在 Decision 等待期间插入新话题，验证实际发送链路的 bot_chat 输入仍使用原快照；最终两条回复闭环复验通过，同时验证显式/归纳简档写入与收发外部消息编号。

`cargo check --workspace --all-targets`、Clippy（保留既有告警）、`npm run build`（含类型检查）、核心改动 rustfmt、手写文件的 Git 空白检查和文档文件链接检查通过；前端产物按仓库规则更新，生成依赖代码中原有的字符串尾部空格未手工改写。

真实 QQ 群聊、线上模型对简档提取/不确定回答的质量评估和生产 V6 迁移尚未执行；测试证明的是组装与约束行为，不是模型幻觉率已经降低某个百分比。本轮不修改服务器运行配置、不自动部署。
