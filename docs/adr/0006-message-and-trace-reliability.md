# 消息可靠恢复，Decision/trace 允许过载缺失

Status: accepted

日期：2026-10-03。对应 Q55，修订 Q37 的全事件完整落库要求。ADR-0005 编号保留给台账中待定的插件设计。

## Decision

消息流水必须可恢复；Decision/trace 是观测数据，允许过载时缺失。现有 broadcast 订阅者会在 Lagged 时跳过事件，因此不能仅靠该总线保证消息处理可恢复。具体持久化消费进度、重试与幂等方案另行设计，当前代码尚未落实。

该决定不承诺消息恰好处理一次，也不改变 Q47 对 NapCat 断线窗未接收消息的容忍。任务业务状态应独立持久化，不能靠不完整 trace 重建。

## Considered Options

- 所有消息、Decision、trace 全部可靠恢复：本轮不采用，增加写入与恢复成本。
- 只保证最终回复：不采用，无法满足消息流水恢复要求。

## Consequences

保留 broadcast 用于实时观测；消息处理需有持久化恢复依据。事件保留 7 天仍是轮转目标，允许 trace 缺失不等于取消事件存储。此 ADR 记录设计裁决，不代表恢复消费与轮转已经实现。
