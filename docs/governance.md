# 云团开发治理协议

> 本文件约束文档、架构与代码如何同步演进，防止"文档活成化石"。

## 1. 单一事实源

- GitHub 仓库 `haotemans/yuantuanbot` 是唯一准星：`docs/`、`docs/adr/`、`src/` 同仓演进，git log 即变更史。
- 本地工作副本 = `D:\weiai\project\rust-agent`（git 克隆，origin 走 SSH）。
- 其他任何本地目录只作镜像，永远不在镜像里改动后再回拷。

## 2. 提交纪律

- **每次更改、每完成一个任务：必须本地 commit + 远程 push，一次一档，不许攒批。**
- 一个任务一个 commit，commit message 格式：`type: subject`
  - type：`docs` / `adr` / `feat` / `fix` / `refactor` / `chore`
  - subject：一句话说清干了什么
- 禁止 force push 到 main；推错就走 revert 新提交。

## 3. 变更分级

- **小改**（字段增删、措辞、参数默认值）：直接改文档 + 修订记录加一行。
- **大改**（难逆转、有真实取舍、推翻已定稿内容）：先写新 ADR（编号递增）。被推翻的旧 ADR 标注 `superseded by ADR-NNNN`，**不删除**——留下当年为什么那样定。

## 4. 冲突裁决

代码与文档冲突时，合法出路只有两条：

1. 改代码迁就文档；
2. 走变更流程改文档。

唯一非法状态：代码悄悄改了，文档没动。AI 协作者在任何实现任务前对照文档检查，撞到即停下报告，由人裁决走哪条。

## 5. 版本节奏

- V0.1：预实现基线（当前）。
- V0.x：实现期迭代，每次定稿递增并记修订记录。
- V1.0：MVP 闭环跑通且逐章核对文档与代码一致，封板；其后只走 ADR 增量。
